# Ролик: сценарий сдачи (не длиннее 7 минут)

Ролик — главный артефакт сдачи. По нему эксперт ставит оценку, сверяя
увиденное с собственным прогоном тестов на вашем коммите. Снимайте экран с
голосом; лицо в кадре не обязательно.

## Требования

- Длительность — **до 7:00**. Что после 7:00, эксперт может не смотреть.
- Скорость воспроизведения 1×. Прогон тестов показывается **целиком, без
  склеек и ускорения**; остальное монтировать можно.
- Терминал и редактор читаемы: шрифт не меньше 16 pt, светлая или тёмная тема —
  неважно, лишние окна закрыты.
- Файл MP4 (или ссылка на YouTube «по ссылке» / Яндекс Диск / Google Drive),
  доступный эксперту без запроса прав.
- Код в ролике — ровно тот коммит, который вы сдаёте (хеш виден в кадре).

## Сценарий

| Время | Что показать | Подсказка |
|---|---|---|
| 0:00–0:30 | **Титул.** ФИО, группа, ссылка на репозиторий, хеш коммита, уровень, на который претендуете (C, B или A) | Хеш покажите командой `git log -1 --format=%H` в терминале, не только на слайде |
| 0:30–2:00 | **Прогон тестов по уровням.** `git status` (рабочая копия чистая), затем `make test-c`, `make test-b`, `make test-a` (или `python tests/run_acceptance.py --level …`) | Итоговые строки `C: x/y, B: …, A: …` должны быть видны и совпасть с прогоном эксперта |
| 2:00–4:00 | **Демонстрация `validate` на 2–3 сломанных конфигурациях.** Возьмите `examples/demo_topic.json` (или свой пример), внесите поломку, покажите её (diff), запустите `validate`, объясните находку: что не так в процессе и чем это грозит | Не берите кейсы из `tests/cases` — сломайте сами. Для уровня A одна из поломок — с `--policy` |
| 4:00–4:45 | **Демонстрация `matrix`.** Запустите на примере, объясните 2–3 ячейки, в том числе неявное право на запись из `inputs` перехода (если оно есть в примере) | Для уровня C достаточно показать, что команда отвечает по контракту |
| 4:45–5:45 | **Одно проектное решение.** Как устроено ваше ядро: представление графа, нормализованная форма, построение матрицы, как избегаете каскада находок… Покажите код | Одно решение, но с «почему так, а не иначе» |
| 5:45–6:40 | **Одна трудность.** Что не получалось, как нашли причину, как решили (или почему не решили) | Например, неочевидное место спецификации и как вы его поняли |
| 6:40–7:00 | **Итог.** Какой уровень сдаёте, что не доделано, сколько часов ушло, какие ИИ-инструменты использовали и для чего | Совпадает с `README_SOLUTION.md` |

## Как эксперт смотрит ролик

1. Сверяет хеш в ролике с хешем в сдаче.
2. Сам клонирует репозиторий на этом хеше, восстанавливает исходные `tests/`
   и запускает тесты (README, раздел «Для эксперта»).
3. Сравнивает итог своего прогона с роликом. Несовпадение — минус одна буква.
4. По демонстрации, проектному решению и трудности оценивает, понимаете ли вы
   свой код (особенно если использовались ИИ-ассистенты), и учитывает
   качество кода и собственных тестов в пределах буквы.

## Чек-лист перед загрузкой

- [ ] длительность не больше 7:00;
- [ ] в кадре хеш коммита, и он совпадает с хешем в сдаче;
- [ ] прогон тестов без склеек, итоговые строки читаемы;
- [ ] 2–3 сломанные конфигурации с объяснением находок и `matrix`;
- [ ] одно проектное решение и одна трудность;
- [ ] ссылка открывается без запроса доступа (проверьте в режиме инкогнито).

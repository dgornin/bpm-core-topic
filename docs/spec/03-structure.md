# 3. Структура процесса: граф, старт, завершение, развилки (S3.*, S5.no_end)

Раздел описывает проверку **графа каждого процесса**: есть ли ровно один старт,
есть ли куда завершиться, достижимы ли узлы, нет ли тупиков и бесконечных
циклов, правильно ли оформлены развилки и возвраты.

Все коды раздела относятся к **уровню C** (см. `tests/levels.json`).
Реализация — модуль `bpmcore/structure.py`.

Примеры корректных процессов: `examples/demo_topic.json` (согласование темы)
и `examples/leave_request.json` (заявка на отпуск: развилка по числу дней,
два возврата на доработку, два исхода).

---

## 3.1. Когда выполняется проверка структуры

1. Сначала выполняется нормализация (коды `S1.*`, см. раздел о нормализации и
   общий порядок в `docs/spec/README.md`). **Если нормализация дала хотя бы одну
   ошибку, анализ структуры не выполняется** и кодов этого раздела в ответе нет.
   Пример: в процессе есть недостижимый узел и переход с `"kind": "forward"`;
   ответ содержит только `S1.flow_kind`, без `S3.unreachable`.
2. Иначе структура проверяется **для каждого процесса из `processes` отдельно**
   (в том числе когда процессов несколько). У каждой находки в `where.process`
   стоит ключ процесса. Находки разных процессов друг на друга не влияют.
3. Проверка структуры не останавливается на первой ошибке: собираются все
   находки (кроме единственного досрочного выхода, описанного в шаге 1
   алгоритма, раздел 3.4).
4. Ошибки структуры не влияют на команду `matrix`: она зависит только от того,
   прошла ли нормализация.

## 3.2. Что гарантирует нормализация

Проверка структуры работает с нормализованным IR. К этому моменту уже
проверено (иначе была бы ошибка `S1.*` и до структуры дело бы не дошло):

* ключи узлов процесса уникальны и корректны, `type` узла — одно из
  `step`, `xor`, `end`;
* у каждого перехода `from` и `to` — ключи узлов **этого же** процесса;
* `kind` перехода — `normal` или `return`; все роли в `by` существуют;
* если у перехода есть ключ `condition`, это корректное условие.

Значения по умолчанию, которые подставляет нормализация и на которые
опирается этот раздел:

| Объект | Поле | По умолчанию |
|---|---|---|
| узел | `type` | `"step"` |
| узел | `start` | `false` |
| переход | `by` | `[]` |
| переход | `auto` | `false` |
| переход | `default` | `false` |
| переход | `system` | `false` |
| переход | `kind` | `"normal"` |
| переход | `condition` | ключа нет (значения по умолчанию нет) |

Флаги `start`, `auto`, `default`, `system` — булевы. В тестах встречаются только
`true`, `false` или отсутствие ключа (= `false`); поведение при небулевых
значениях не проверяется.

## 3.3. Термины

* **Узел** — элемент `nodes` процесса. По `type` различаем: **шаг** (`step`,
  с документом работает человек), **развилка** (`xor`, движок сам выбирает один
  из выходов по условиям), **конечный узел** (`end`, процесс завершён).
* **Стартовый узел** — узел с `"start": true`. В нём оказывается только что
  созданный документ.
* **Переход** — элемент `flows` процесса: ребро из узла `from` в узел `to`.
* **Выходы узла** `n` — все переходы процесса с `from = n` (в любом количестве,
  в том числе петли `from = to`). Выходы развилки называем **выходами развилки**.
* **Граф процесса** — ориентированный граф: вершины — все узлы процесса, рёбра —
  **все** переходы процесса без исключений (обычные и `return`, `auto` и ручные,
  системные, а также переходы из конечных узлов, хотя они сами по себе ошибка).
  Кратные рёбра и петли допустимы.
* **Достижимость.** Узел `v` достижим из узла `u`, если в графе процесса есть
  путь из `u` в `v`. Путь длины 0 тоже считается: **каждый узел достижим из
  самого себя**. Обозначение: `R(u)` — множество узлов, достижимых из `u`
  (всегда содержит `u`).
* **Достижимый узел** (без уточнения) — узел, достижимый из стартового.
* **Переход «пуст по `by`»** — у перехода `by` равен `[]`.
* **У перехода есть условие** — в объекте перехода присутствует ключ `condition`.

## 3.4. Алгоритм проверки одного процесса

Ниже `P` — ключ процесса, `N` — его узлы, `F` — его переходы. Шаги 2–6 не
зависят друг от друга: набор находок не зависит от порядка их выполнения.
Порядок находок в ответе не важен.

**Шаг 1. Старт.** Пусть `S` — множество стартовых узлов.

* Если `|S| ≠ 1` (стартовых нет или их несколько) — ошибка `S3.start`
  с `where = {process: P}`. **Дальше процесс не проверяется: шаги 2–6 не
  выполняются** (никаких других находок этого раздела для `P`; см. также
  раздел 3.8 про `A6.no_trigger`).
* Иначе пусть `s` — единственный стартовый узел. Если его `type` не `step` —
  ошибка `S3.start` с `where = {process: P, node: s}`, **проверка продолжается**
  (достижимость считается от `s`).

**Шаг 2. Наличие конца.** Если в `N` нет ни одного узла с `type = end` —
ошибка `S3.end`, `where = {process: P}`.

**Шаг 3. Достижимость.** Для каждого узла `n ∉ R(s)` — ошибка
`S3.unreachable`, `where = {process: P, node: n}`.

**Шаг 4. Выходы узлов.** Для **каждого** узла `n` (достижимого или нет):

1. `n` — конечный узел: если у него есть хотя бы один выход — ошибка
   `S3.end_out`, `where = {process: P, node: n}` (одна на узел, сколько бы
   выходов ни было). Других проверок выходов конечного узла нет (их `auto`, `by`
   и т.п. не проверяются). Переходим к следующему узлу.
2. Иначе, если у `n` нет выходов — ошибка `S3.dead_end`,
   `where = {process: P, node: n}`. Переходим к следующему узлу
   (для развилки без выходов `S3.xor` и `S3.xor_default` **не** выдаются).
3. `n` — развилка (`xor`), у неё `k ≥ 1` выходов:
   * если `k < 2` — ошибка `S3.xor`, `where = {process: P, node: n}`;
   * если число выходов с `"default": true` не равно 1 — ошибка
     `S3.xor_default`, `where = {process: P, node: n}` (одна на развилку);
   * для каждого выхода `f` независимо проверяются три условия (один выход
     может дать несколько кодов):
     * `auto` ложно — ошибка `S3.xor_auto`, `where = {process: P, flow: f}`;
     * `default` ложно и у `f` нет условия — ошибка `S3.xor_condition`,
       `where = {process: P, flow: f}`;
     * `by` не пуст — ошибка `S3.xor_by`, `where = {process: P, flow: f}`.
4. `n` — шаг (`step`): для каждого выхода `f` с истинным `auto` — ошибка
   `S3.auto`, `where = {process: P, flow: f}`.

**Шаг 5. Завершаемость.** Пусть `E` — множество конечных узлов. Для каждого
**достижимого** узла `n` (то есть `n ∈ R(s)`, включая сам `s` и конечные узлы):
если `R(n) ∩ E = ∅` — ошибка `S5.no_end`, `where = {process: P, node: n}`.
Недостижимые узлы на шаге 5 не проверяются.

**Шаг 6. Возвраты.** Для **каждого** перехода `f` с `kind = return` (в том числе
из недостижимых узлов): если `f.from ∉ R(f.to)` — **предупреждение**
`S3.return`, `where = {process: P, flow: f}`.

Псевдокод (не привязан к языку):

```
check_process(P):
    S = [n in N if n.start]
    if |S| != 1: error S3.start {process}; return
    s = S[0]
    if s.type != step: error S3.start {process, node: s}
    if no n in N with n.type == end: error S3.end {process}
    Rs = reach(s)
    for n in N: if n not in Rs: error S3.unreachable {process, node: n}
    for n in N:
        out = [f in F if f.from == n]
        if n.type == end:
            if out: error S3.end_out {process, node: n}
            continue
        if not out: error S3.dead_end {process, node: n}; continue
        if n.type == xor:
            if |out| < 2: error S3.xor {process, node: n}
            if |[f in out if f.default]| != 1: error S3.xor_default {process, node: n}
            for f in out:
                if not f.auto: error S3.xor_auto {process, flow: f}
                if not f.default and "condition" not in f: error S3.xor_condition {process, flow: f}
                if f.by: error S3.xor_by {process, flow: f}
        else:  # step
            for f in out:
                if f.auto: error S3.auto {process, flow: f}
    E = {n in N if n.type == end}
    for n in Rs: if reach(n) ∩ E is empty: error S5.no_end {process, node: n}
    for f in F if f.kind == return:
        if f.from not in reach(f.to): warning S3.return {process, flow: f}

reach(u): обход в ширину или глубину по графу процесса от u; результат содержит u.
```

## 3.5. Сводка кодов

| Код | Уровень | Находка | Где (`where`) | Кратко |
|---|---|---|---|---|
| `S3.start` | C | error | `process` или `process`, `node` | не ровно один старт / старт не шаг |
| `S3.end` | C | error | `process` | нет ни одного конечного узла |
| `S3.end_out` | C | error | `process`, `node` | из конечного узла есть переходы |
| `S3.unreachable` | C | error | `process`, `node` | узел не достижим от старта |
| `S3.dead_end` | C | error | `process`, `node` | не конечный узел без выходов |
| `S3.auto` | C | error | `process`, `flow` | `auto` у перехода из шага |
| `S3.xor` | C | error | `process`, `node` | у развилки меньше двух выходов |
| `S3.xor_default` | C | error | `process`, `node` | выходов по умолчанию не ровно один |
| `S3.xor_auto` | C | error | `process`, `flow` | выход развилки без `auto` |
| `S3.xor_condition` | C | error | `process`, `flow` | выход развилки без условия и не по умолчанию |
| `S3.xor_by` | C | error | `process`, `flow` | у выхода развилки непустой `by` |
| `S5.no_end` | C | error | `process`, `node` | из достижимого узла не дойти до конца |
| `S3.return` | C | **warning** | `process`, `flow` | возврат не замыкает цикл |

`where.node` — ключ узла, `where.flow` — ключ перехода, `where.process` — ключ
процесса. Тесты сравнивают только коды, вердикт и код выхода; `message` и
`where` не сравниваются, но заполняйте `where` ровно этими ключами: по нему
аналитик находит место ошибки. Одна находка выдаётся на каждый узел или
переход, указанный в `where` (например, два недостижимых узла — две находки
`S3.unreachable`). Единственное предупреждение раздела — `S3.return`: оно не
меняет вердикт (если других ошибок нет, вердикт `accept`).

В примерах ниже показаны только изменённые фрагменты процесса; остальное — как
в `examples/demo_topic.json` (узлы `draft` → `review` → `published` /
`rejected`, возврат `rework` из `review` в `draft`).

## 3.6. Коды по одному

### S3.start — старт процесса

* **Уровень:** C. **Находка:** error.
* **Условие:** (а) число узлов с `"start": true` не равно 1 — `where = {process}`,
  остальные проверки структуры процесса не выполняются; (б) старт один, но его
  `type` не `step` — `where = {process, node: <старт>}`, проверки продолжаются.
* **Почему ошибка:** документ создаётся в стартовом узле, и там с ним работает
  создатель. Без старта или с двумя стартами неизвестно, где документ
  окажется; развилка или конечный узел не могут быть местом работы создателя.
* **Пример:**

  ```json
  "nodes": [
    {"key": "draft", "name": "Черновик", "start": true},
    {"key": "review", "name": "На утверждении", "start": true}
  ]
  ```

  → `S3.start`, `where = {"process": "topic"}`.
* **Важно:** при варианте (а) в процессе не ищутся ни недостижимые узлы, ни
  тупики, ни ошибки развилок — даже если они есть. При варианте (б) все
  остальные проверки выполняются: например, если стартом объявлен конечный
  узел `published` без выходов, будут ещё `S3.unreachable` для всех узлов,
  кроме `published`.
* **Кейсы:** `tests/cases/st-start-missing`, `st-start-two`,
  `st-start-not-step` (старт — развилка), `st-start-second-process` (ошибка во
  втором процессе приложения, `where.process = "meeting"`).

### S3.end — нет конечного узла

* **Уровень:** C. **Находка:** error. **Где:** `{process}`.
* **Условие:** в процессе нет ни одного узла с `"type": "end"`.
* **Почему ошибка:** процесс не может завершиться.
* **Сопутствующие коды:** при `S3.end` множество `E` пусто, поэтому
  `S5.no_end` выдаётся для **каждого** достижимого узла (включая старт).
* **Пример (забыли `type`):**

  ```json
  {"key": "published", "name": "Опубликована"},
  {"key": "rejected", "name": "Отклонена"}
  ```

  → `S3.end`; `S3.dead_end` для `published` и `rejected` (теперь это шаги без
  выходов); `S5.no_end` для `draft`, `review`, `published`, `rejected`.
* **Кейсы:** `st-end-missing`.

### S3.end_out — переход из конечного узла

* **Уровень:** C. **Находка:** error. **Где:** `{process, node}`.
* **Условие:** у узла с `"type": "end"` есть хотя бы один выход. Одна находка на
  узел.
* **Почему ошибка:** конечный узел означает, что процесс завершён; из него
  никуда не переходят.
* **Детали:** выходы конечного узла больше ничем не проверяются (ни `S3.auto`,
  ни `A6.no_trigger`, см. 3.8), но они остаются рёбрами графа: узел, в который
  ведёт только переход из конечного узла, считается достижимым.
* **Пример:**

  ```json
  {"key": "reopen", "label": "Вернуть в работу", "from": "published", "to": "draft", "by": ["author"]}
  ```

  → `S3.end_out`, `where = {"process": "topic", "node": "published"}`.
* **Кейсы:** `st-end-out`.

### S3.unreachable — недостижимый узел

* **Уровень:** C. **Находка:** error. **Где:** `{process, node}`.
* **Условие:** узел не входит в `R(s)` — от стартового узла до него нет пути по
  переходам (любого вида, включая `return`). Одна находка на узел.
* **Почему ошибка:** в такой узел документ никогда не попадёт: забыт переход
  или узел лишний.
* **Детали:** недостижимые узлы проходят проверки шага 4 (поэтому недостижимый
  шаг без выходов даёт ещё и `S3.dead_end`), но не проверяются на шаге 5
  (`S5.no_end` для них не выдаётся). Узел, в который ведёт только возврат
  (`kind: return`), достижим.
* **Пример:**

  ```json
  {"key": "archived", "name": "В архиве", "type": "end", "result": "cancelled"}
  ```

  (узел добавлен, переходов в него нет) → `S3.unreachable` для `archived`.
* **Кейсы:** `st-unreachable`, `st-unreachable-dead-end` (недостижимый шаг без
  выходов: `S3.unreachable` + `S3.dead_end`, без `S5.no_end`),
  `st-return-only-path-accept` (зелёный: узел достижим только через возврат),
  `st-several-errors`.

### S3.dead_end — тупик

* **Уровень:** C. **Находка:** error. **Где:** `{process, node}`.
* **Условие:** узел не конечный (`step` или `xor`) и у него нет ни одного выхода.
  Проверяются все узлы, а не только достижимые.
* **Почему ошибка:** документ, попавший в такой узел, застрянет в нём навсегда.
* **Детали:** развилка без выходов даёт `S3.dead_end`, а `S3.xor` и
  `S3.xor_default` для неё не выдаются. Если тупик достижим, для него будет и
  `S5.no_end` (из тупика не дойти до конца).
* **Пример:**

  ```json
  "nodes": [..., {"key": "on_hold", "name": "Отложена"}],
  "flows": [..., {"key": "hold", "label": "Отложить", "from": "review", "to": "on_hold", "by": ["head"]}]
  ```

  → `S3.dead_end` и `S5.no_end` для `on_hold`.
* **Кейсы:** `st-dead-end`, `st-xor-no-exits` (развилка без выходов),
  `st-unreachable-dead-end`, `st-end-missing`.

### S5.no_end — из узла нельзя завершиться

* **Уровень:** C. **Находка:** error. **Где:** `{process, node}`.
* **Условие:** узел достижим от старта, и из него недостижим ни один конечный
  узел (`R(n) ∩ E = ∅`). Конечный узел достижим из самого себя, поэтому для
  конечных узлов `S5.no_end` не бывает (если конечные узлы вообще есть).
* **Почему ошибка:** попав в такой узел, документ уже никогда не завершит
  процесс — будет ходить по циклу или застрянет.
* **Пример (цикл без выхода, тупика формально нет):**

  ```json
  "nodes": [..., {"key": "on_hold", "name": "Отложена"}],
  "flows": [...,
    {"key": "hold", "label": "Отложить", "from": "review", "to": "on_hold", "by": ["head"]},
    {"key": "prolong", "label": "Продлить ожидание", "from": "on_hold", "to": "on_hold", "by": ["author"]}]
  ```

  → только `S5.no_end` для `on_hold` (у `review` есть путь к `published`).
* **Кейсы:** `st-no-end-loop` (только этот код), `st-dead-end`,
  `st-xor-no-exits`, `st-end-missing`.

### S3.auto — автоматический переход из шага

* **Уровень:** C. **Находка:** error. **Где:** `{process, flow}`.
* **Условие:** переход выходит из шага (`type = step`) и у него `"auto": true`.
* **Почему ошибка:** автоматически (без нажатия кнопки) движок выбирает только
  выходы развилки; из шага переход выполняет человек.
* **Детали:** для такого перехода `A6.no_trigger` не выдаётся, даже если
  `by` пуст (см. 3.8).
* **Пример:**

  ```json
  {"key": "submit", "from": "draft", "to": "review", "by": ["author"], "auto": true}
  ```

  → `S3.auto`, `where = {"process": "topic", "flow": "submit"}`.
* **Кейсы:** `st-auto-step`, `st-several-errors`.

### Развилка (xor): общие правила

Развилка — узел, в котором движок сам выбирает **ровно один** выход:
выходы с условием проверяются, а если ни одно условие не выполнилось,
берётся выход по умолчанию. Отсюда требования к развилке с `k ≥ 1` выходами:

* выходов не меньше двух (`S3.xor`);
* ровно один выход с `"default": true` (`S3.xor_default`);
* каждый выход `"auto": true` (`S3.xor_auto`);
* каждый выход, кроме выхода по умолчанию, имеет `condition`
  (`S3.xor_condition`); выход по умолчанию **может** иметь условие — это не
  ошибка;
* ни у одного выхода нет ролей в `by` (`S3.xor_by`).

Проверки независимы: одна развилка может дать сразу несколько кодов
(например, единственный выход без `default` → `S3.xor` и `S3.xor_default`).
Корректная развилка:

```json
"nodes": [..., {"key": "route", "name": "Есть описание?", "type": "xor"}, ...],
"flows": [...,
  {"key": "approve", "from": "review", "to": "route", "by": ["head"]},
  {"key": "publish", "from": "route", "to": "published", "auto": true,
   "condition": {"field": "x_description", "op": "set"}},
  {"key": "back_to_author", "from": "route", "to": "draft", "auto": true, "default": true}]
```

Зелёные кейсы с развилками: `st-xor-accept`, `st-leave-accept`.

Структура не проверяет у выходов развилки `system`, `kind` и прочие поля, а у
переходов из шагов — `default` (игнорируется) и `condition` (у перехода из шага
условие допустимо: оно ограничивает, когда кнопка доступна).

### S3.xor — у развилки меньше двух выходов

* **Уровень:** C. **Находка:** error. **Где:** `{process, node}`.
* **Условие:** узел `xor` имеет ровно один выход (при нуле выходов — `S3.dead_end`
  вместо `S3.xor`).
* **Почему ошибка:** развилка с одним выходом ничего не выбирает.
* **Пример:** у `route` только
  `{"key": "publish", "from": "route", "to": "published", "auto": true, "default": true}`
  → `S3.xor` для `route` (и больше ничего: выход единственный, но он по
  умолчанию, `auto` и без `by`).
* **Кейсы:** `st-xor-single-exit`.

### S3.xor_default — выход по умолчанию не ровно один

* **Уровень:** C. **Находка:** error. **Где:** `{process, node}` — одна находка на
  развилку, а не на выход.
* **Условие:** у развилки с хотя бы одним выходом число выходов с
  `"default": true` равно 0 или больше 1.
* **Почему ошибка:** если выхода по умолчанию нет, а ни одно условие не
  выполнилось, процесс застрянет; если их несколько, выбор неоднозначен.
* **Пример (нет выхода по умолчанию):**

  ```json
  {"key": "publish", "from": "route", "to": "published", "auto": true, "condition": {"field": "x_description", "op": "set"}},
  {"key": "back_to_author", "from": "route", "to": "draft", "auto": true, "condition": {"field": "x_description", "op": "unset"}}
  ```

  → `S3.xor_default` для `route`.
* **Кейсы:** `st-xor-no-default`, `st-xor-two-defaults`.

### S3.xor_auto — выход развилки не автоматический

* **Уровень:** C. **Находка:** error. **Где:** `{process, flow}` — на каждый такой
  выход.
* **Условие:** у выхода развилки `auto` ложно (в том числе ключ не указан).
* **Почему ошибка:** выходы развилки выбирает движок, а не человек.
* **Пример:** `{"key": "publish", "from": "route", "to": "published", "condition": {...}}`
  (нет `"auto": true`) → `S3.xor_auto` для `publish`.
* **Кейсы:** `st-xor-not-auto`.

### S3.xor_condition — у выхода развилки нет условия

* **Уровень:** C. **Находка:** error. **Где:** `{process, flow}`.
* **Условие:** выход развилки не помечен `"default": true` и в нём нет ключа
  `condition`.
* **Почему ошибка:** движку не по чему решить, когда выбирать этот выход.
* **Пример:** `{"key": "publish", "from": "route", "to": "published", "auto": true}`
  при другом выходе по умолчанию → `S3.xor_condition` для `publish`.
* **Кейсы:** `st-xor-no-condition`.

### S3.xor_by — у выхода развилки указаны роли

* **Уровень:** C. **Находка:** error. **Где:** `{process, flow}`.
* **Условие:** у выхода развилки непустой `by`.
* **Почему ошибка:** выход развилки не нажимает человек, поэтому список ролей,
  которые могут его выполнить, бессмыслен и вводит в заблуждение.
* **Пример:**
  `{"key": "publish", "from": "route", "to": "published", "auto": true, "by": ["author"], "condition": {...}}`
  → `S3.xor_by` для `publish`.
* **Детали:** если роль из такого `by` к тому же не видит документ в узле
  развилки, раздел об участниках добавит ещё `A6.by_read` (уровень B); в кейсе
  `st-xor-by` роль `author` видит документ во всех узлах, поэтому там только
  `S3.xor_by`.
* **Кейсы:** `st-xor-by`.

### S3.return — возврат не замыкает цикл (предупреждение)

* **Уровень:** C. **Находка:** **warning** (вердикт не меняет). **Где:**
  `{process, flow}`.
* **Условие:** у перехода `"kind": "return"`, и узел `from` недостижим из узла
  `to` (`from ∉ R(to)`). Проверяются все переходы-возвраты, в том числе из
  недостижимых узлов.
* **Смысл:** «возврат» — это отправка документа назад, на доработку, после
  которой он снова должен прийти туда, откуда его вернули. Если из `to` нельзя
  снова попасть в `from`, переход на самом деле ведёт вперёд или вбок и помечен
  как возврат по ошибке.
* **Не предупреждение:** возврат-петля (`from = to`): узел достижим из самого
  себя. Возврат на несколько шагов назад (как `hr_rework` из `hr_review` в
  `draft` в `examples/leave_request.json`) корректен, если из `draft` по
  переходам снова можно дойти до `hr_review`.
* **Пример:**

  ```json
  {"key": "reject", "from": "review", "to": "rejected", "by": ["head"], "kind": "return"}
  ```

  Из конечного `rejected` в `review` не попасть → `S3.return` для `reject`,
  вердикт `accept` (если других ошибок нет).
* **Кейсы:** `st-return-forward` (вердикт `accept` с предупреждением),
  `st-several-errors`; зелёные с корректными возвратами — `st-demo-accept`,
  `st-leave-accept`, `st-return-only-path-accept`.

## 3.7. Частые сочетания кодов (следствия алгоритма)

| Ситуация | Коды |
|---|---|
| нет стартового узла или их несколько | только `S3.start` (без `where.node`), остальное в процессе не проверяется |
| старт — не шаг | `S3.start` с `where.node` + всё, что найдут шаги 2–6 |
| нет конечных узлов | `S3.end` + `S5.no_end` на каждом достижимом узле |
| достижимый тупик | `S3.dead_end` + `S5.no_end` на нём |
| недостижимый тупик | `S3.unreachable` + `S3.dead_end` (без `S5.no_end`) |
| развилка без выходов | `S3.dead_end` (+ `S5.no_end`, если достижима), без `S3.xor` |
| развилка с одним выходом не по умолчанию | `S3.xor` + `S3.xor_default` (+ `S3.xor_condition`, если у выхода нет условия) |
| цикл без выхода к концу | только `S5.no_end` на узлах цикла |

## 3.8. Связь с A6.no_trigger (уровень B)

Код `A6.no_trigger` («переход никто не может выполнить») относится к разделу
об участниках и реализуется вместе с другими `A6.*` (`bpmcore/access.py`), но
условие его выдачи сформулировано в терминах структуры, поэтому приводим его
здесь точно. Ошибка `A6.no_trigger` с `where = {process: P, flow: f}` выдаётся
для перехода `f` процесса `P`, если выполнены **все** условия:

1. в процессе ровно один стартовый узел (при `|S| ≠ 1` код не выдаётся ни для
   одного перехода процесса; если старт один, но не шаг, — выдаётся);
2. `f` выходит из шага (`type = step`), достижимого или нет; для выходов
   развилок и конечных узлов код не выдаётся;
3. `auto` у `f` ложно (автоматический переход из шага даёт `S3.auto`, а не
   `A6.no_trigger`);
4. `by` у `f` пуст и `system` ложно.
